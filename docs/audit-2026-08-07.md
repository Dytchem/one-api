# one-api 代码审计报告（2026-08-07）

审计方式：多角色分组评审（安全审计 / 正确性与并发 / 性能 / 代码质量 / 测试验证），
覆盖 `common/`、`controller/`、`middleware/`、`model/`、`monitor/`、`relay/`、`router/`、`pi-bridge/`。
fork 已包含大量 dyt-XX 加固（会话回查、SSRF 钉 IP、审计脱敏、验证码防爆破等），本轮在其基础上继续收敛残留问题。

## 一、安全（Security）

| # | 严重度 | 位置 | 问题 | 修复 |
|---|--------|------|------|------|
| S1 | 高 | `GET /api/oauth/email/bind`、`GET /api/oauth/wechat/bind` | Cookie 会话 + GET 状态变更接口 = CSRF。攻击者可用自己的邮箱验证码诱导受害者点击链接，把攻击者邮箱绑定到受害者账号，随后走"忘记密码"接管账号（SameSite=Lax 不拦顶层 GET 导航）。dyt-96 已把 `/user/token` 从 GET 改 POST，本处遗漏 | 新增 `SameOriginGuard` 中间件：要求 Origin/Referer 与当前 host 同源，两者皆缺或跨源直接拒绝；应用到两个 bind 路由（不改前端协议，避免强制重建 web/build） |
| S2 | 中 | `model/cache.go` `CacheIsUserEnabled` / `CacheGetUserGroup` | Redis `SET` 失败（抖动/降级）时把错误返回给调用方 → TokenAuth 直接 500/403。缓存写失败不应阻断请求（读路径已经 fail-open 回源 DB） | SET 失败仅记日志，返回 DB 现值 |
| S3 | 低 | `middleware/auth.go` authHelper | `id.(int)`、`status.(int)`、`role.(int)` 无 ok 断言，异常会话类型直接 panic→500 | 改安全断言，类型不符按未登录处理 |
| S4 | 低 | `GetAllUsers`/`GetAllTokens`/`GetAllLogs` 等 | `size` 查询参数无上限，可构造超大分页拖慢 DB / 打大响应 | 统一上限 200 |

## 二、正确性与并发（Correctness）

| # | 严重度 | 位置 | 问题 | 修复 |
|---|--------|------|------|------|
| C1 | 高 | `model/log.go` `SearchUserLogs` | `Where("user_id = ? and type = ?", userId, keyword)`：int 列对字符串比较。PostgreSQL 直接报错→500；MySQL 隐式转换语义错误；SQLite 恒不匹配。前端"日志搜索"（/api/log/self/search）实际不可用 | 与 `SearchAllLogs` 对齐：`content LIKE keyword%` |
| C2 | 高 | `model/channel.go` `DeleteDisabledChannel`/`DeleteChannelByStatus` | 批量删渠道不清理 `abilities` 表 → 孤儿 ability 行使健康路由选中不存在的渠道，报"数据库一致性已被破坏"，该模型路由不可用 | 删除前取 id 列表，同事务清理 abilities + `RemoveChannelMetrics` + 刷新内存渠道缓存 |
| C3 | 中 | `controller/user.go` `ManageUser` delete 分支 | `user.Delete()` 成功后 fallthrough 到 `user.Update(false)`，对已删除用户做多余全字段回写 | delete 成功后直接返回 |
| C4 | 中 | `model/user.go` `UpdateUserRole` | 未失效进程内用户缓存（`DeleteUserMemCache`），降权后最长一个 SyncFrequency 窗口内旧角色仍生效 | 补缓存失效 |
| C5 | 中 | `monitor/sliding.go` `ResetChannelMetrics` | 只清窗口不清原子快照（successes/failures/tokens/elapsed/probes/valid）→ 重置后健康分长期错误 | 重置时同步清零快照 |
| C6 | 中 | `monitor/sliding.go` `GetRecentTTFT` | 未加锁先读 `m.count`（与写路径竞争，Go race detector 可报） | 先取 RLock 再读 |
| C7 | 中 | `relay/controller/text.go` 非流式空响应检测 | 检测发生在 `adaptor.DoResponse` 已把响应写给客户端之后；返回 502 触发 Relay() 换渠道重试 → 同一响应体写两份，客户端收到拼接的非法 JSON | OpenAI 兼容渠道改为先整体读入 body、判空后再写出（与 Responses 路径一致）；其余渠道用 `c.Writer.Written()` 兜底，已写出则不再触发重试 |
| C8 | 低 | `model/cache.go` `CacheGetUserQuota` | Redis 值解析失败返回 `(0, nil)`，吞错误 | 返回 error |
| C9 | 低 | `model/log.go` `BackfillFailFlags` | 回填用宽松 `LIKE '%HTTP %'`，与收紧后的 `isFailContent`（正则 `HTTP [1-5]\d\d`）不一致，会误标含 "HTTP " 字样的成功日志 | 回填改为 `HTTP 1%`~`HTTP 5%` 五个模式，与正则口径一致 |
| C10 | 低 | `controller/user.go` `GetUserDashboard` | `Truncate(24h)` 以 UTC 零点为日界，非 UTC 时区统计错位 | 用本地时区 `time.Date` 取当日零点 |
| C11 | 低 | `controller/user.go` `DeleteSelf` | 删除自己后未清会话（虽有 DB 回查兜底，cookie 仍残留） | 清 session |
